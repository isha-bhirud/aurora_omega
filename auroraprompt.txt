AURORA — BUILD SPECIFICATION FOR ANTIGRAVITY
Aircraft & Unified Runway Operations Records Archive

PURPOSE
Build a working, database-focused academic project named AURORA. It is a relational database application for managing aircraft, airlines, aircraft types, airports, runway infrastructure, flight records, predefined landing/takeoff schedules, and manually recorded runway assignments.

IMPORTANT SCOPE LIMITS
- This is primarily a MySQL database/DBMS concepts project with a usable frontend UI.

- icao_code: nullable unique code
- country
- callsign
- operating_status

- type_id: primary key
- manufacturer
- model
- variant

- longitude
- elevation

- runway_length
- runway_width

- runway_status (OPEN, CLOSED, RESTRICTED, MAINTENANCE)
- notes

- taxiway_name

- actual_datetime: nullable
- operation_status (SCHEDULED, DELAYED, CANCELLED, COMPLETED)

12. AIRCRAFT_RUNWAY_COMPATIBILITY

- end_datetime
- maintenance_type
- maintenance_status

- airport_id: foreign key to AIRPORT
- day_of_week
- opening_time

17. AIRPORT_MAP

SCHEMA RULES
- Use InnoDB and sensible data types (DECIMAL for dimensions/weights, DATE for dates, DATETIME or TIMESTAMP consistently for times, VARCHAR for identifiers).
- Define all PKs, FKs, NOT NULL, UNIQUE, CHECK constraints supported by the chosen MySQL version, and indexes intentionally.
- Use ON DELETE/UPDATE actions deliberately. Avoid cascading deletes that could erase flight history.
- Enforce positive runway length/width and valid enum-like values through CHECK constraints or reference tables.
- Use nullable unique airport codes if codes are unknown; confirm MySQL's NULL behavior.
- Normalize the schema and document important functional dependencies. Avoid duplicating manufacturer/model in AIRCRAFT when they belong in AIRCRAFT_TYPE.
- Do not store counts such as number_of_runways if they can be derived from RUNWAY.
- Keep actual flight timing, schedule timing, aircraft identity, and runway assignment separate.
- Avoid storing computed eligibility or availability as permanent facts if it can become stale; calculate validation from current runway, compatibility, restriction, and operation data.
- Use migrations or versioned SQL scripts so the database can be recreated consistently.
